# kid-explainer（小学生でもわかる before/after 図解）

対象（PR・issue・コード・仕組み）を調べ、**身近なたとえ 1 つ**で説明し、**BEFORE / AFTER の図**を並べた
1 枚の HTML を Artifact として公開して URL を返す。読み手は社内の人（エンジニアでない人を含む）。

骨組みは `templates/explainer.html`。毎回ここからコピーして中身を埋める（ゼロから書かない）。

## 手順

### ① 対象を根拠から調べる

- PR なら `gh pr view` / `gh pr diff`、issue なら `gh issue view`、コードなら実際のファイルを読む。
  動かせるなら動かして確かめる。
- 読んだファイル・行番号・コミット・URL・計測コマンドをメモしておく（⑥の根拠の節に使う）。
- **確かめていないことは推測と書く。** 本文では `<span class="guess">（推測）</span>` を付ける。
- 依頼文や README に書かれた説明・数字は、コードや実測と食い違うことがある。食い違いを見つけたら
  本文に「README では X、実際は Y」と両方書く。

### ② たとえを 1 つだけ選ぶ

- お店・工場・引き出し・郵便・図書館・名簿・受付番号など、小学生が毎日見ているものから 1 つ選ぶ。
- **ページ全体でそのたとえだけを使い回す。** 途中で別のたとえに乗り換えない（読み手が対応を覚え直すことになる）。
- 冒頭（`header` の `.note`）で「〇〇を△△にたとえます」と宣言する。

### ③ BEFORE / AFTER を図にする（2〜4 枚）

- 1 枚 = 1 場面。左に BEFORE（困っていること）、右に AFTER（どう解決したか）。
  PC では横並び、640px 以下では縦に積む（テンプレートの `.pair` がそうなっている）。
- 図は inline SVG で手書きする。BEFORE と AFTER は**同じ viewBox・同じ配置**にして、変わったところだけが目に入るようにする。
- 各パネルの下に 1〜2 文の説明（`.panel p`）。図の下に「本物の話」（`.real`）を置き、たとえを外した説明・数字・ファイル名はそこに書く。
- `svg` には `role="img"` と `aria-label`（図の中身を 1 文で）を付ける。
- 図は 4 枚まで。言いたいことが 5 つ以上あるなら、図にするのは大事な順に 4 つまでにし、残りは表か箇条書きにする。

### ④ 「たとえ ↔ 本物の言葉」の対応表

- 列は「たとえ / 本物の言葉 / どこで確かめたか」。本文で使ったたとえは全部この表に載せる。
- 専門用語は本文に出さず、この表に寄せる（本文に出すなら 1 回だけ、括弧で）。

### ⑤ 注意・まだ分からないこと

- 引き換えにしたもの、できないこと、測っていないこと、確かめていないことを箇条書きで書く。
- 読んだ人に決めてほしいこと・次にやることがあれば `.callout` に 1〜2 文で。

### ⑥ 根拠

- PR・issue の URL、読んだファイル（ブランチ・コミット付き）、動かしたコマンドと環境を箇条書きで書く。

## ページの規約（Artifact の規約に合わせる）

テンプレートはこの規約を満たしている。埋めるときに崩さないこと。

- `<title>` は 2〜4 語の名前（例: 「mach-gl はなぜ速い」「受付番号ジョブ図解」）。「〇〇: 解説」のような形にしない。
- 色はすべて `:root` のトークン。ダークモードは `@media (prefers-color-scheme: dark)` の中の
  `:root:not([data-theme="light"])` と、`:root[data-theme="dark"]` の**両方**に同じ値を書く。
- `body` に背景色（`var(--bg)`）。
- 外部スクリプトは読み込まない。外部の stylesheet は Google Fonts だけ。
- 幅 390px で横スクロールしない。左右の余白は 16px（`main` の `padding-inline`）。
  横に長い SVG と表だけは、横スクロールの枠（`.fig` / `.tablewrap`）に入れてよい。
- **SVG の色もトークンから。** `fill="#..."` や `style="fill:#..."` を直書きせず、`.s-xxx`（図形）・`.t-xxx`（文字）のクラスを使う。
  足りないクラスは `<style>` に足す。例外は `--hi`（黄色）の上に乗せる文字の `.t-on-hi` だけ（両テーマで背景が明るいため固定色）。
- `.summary` / `.pair` / `.panel` などのグリッドの子には `min-width: 0`（長いコードで横にはみ出さないため。テンプレートは設定済み）。

## 文体

- 社内向け。小学生でもわかる言葉で、1 文を短く。「です・ます」でそろえる。
- 言い切りすぎない。確かめたことは言い切り、推測は「〜と見ています」「（推測）」と書き分ける。
- 専門用語は対応表へ。本文はたとえの言葉で通す。
- 数字は「本物の話」と表に書き、単位と測った環境を添える。

## 出力と公開

1. テンプレートをスクラッチパッド（無ければ作業ディレクトリの外の一時フォルダ）にコピーして埋める。
   ファイル名は `<対象>-explainer.html`。TODO と 〇〇 が残っていないことを `grep -n 'TODO\|〇〇'` で確かめる。
2. Playwright が使えるなら、次の 3 つでスクリーンショットを撮って見る:
   - PC（幅 1280px 前後）
   - スマホ（幅 390px）: `document.documentElement.scrollWidth <= 390` であること（横スクロールしない）
   - ダーク（`prefers-color-scheme: dark` をエミュレートするか、`<html data-theme="dark">` にする）:
     文字や図形が背景に溶けていないこと
   使えないときは、確かめていないことを返答に書く。
3. **publish の前に HTML を全文読む。**
4. Artifact ツールで公開する。`icon` は 1 語の一般名詞（`diagram` / `chart` / `book` など。製品名は使わない）、
   `description` は 1 文。
5. 返答に URL と、図にした場面（1 行ずつ）、推測のまま残したことを書く。

### 司令官（commander）が部下に書かせるとき

- **部下が HTML を書き、公開は司令官**が行う。部下は Artifact を publish しない。
- 部下は HTML をスクラッチパッドに書き、Playwright で確かめたスクリーンショットのパスと HTML のパスを STATUS.md に書いて止まる。
- 司令官は HTML を全文読んでから publish し、URL を人間に返す。
